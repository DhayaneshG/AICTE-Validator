# DECISIONS.md

1. **Python 3.11** venv (`python3.11` is available alongside the sandbox default 3.13), matching the brief.
2. **Capability count:** the brief's list sums to 38 rows (27 built-target, 4 mocked, 7 planned) although it states 26/37. All 38 rows are tracked; final counts are computed from FEATURES.md.
3. **SQLite via SQLAlchemy 2.x**, portable to Postgres (no SQLite-only SQL).
4. **API under `/api`**, built Vite output served from FastAPI at `/`. `/health` is exposed at both `/api/health` and `/health`.
5. **Tesseract** exists in the sandbox but RapidOCR remains the primary OCR per the brief.
6. **Advisory framing:** findings are indicators for human review; a persistent UI banner states this.
7. **Authenticity:** every metric in docs comes from scripts in `eval/`; simulated components are labelled MOCK.
8. **Sandbox network:** only PyPI/npm/GitHub reachable; nothing needs outbound network at runtime.

9. **Absent QR reference -> status `mismatch` (reason `not_found`).** The brief's status list (verified|mismatch|expired|pending|source_unavailable|manual_review) has no "not found"; a reference that the registry does not know is reported as `mismatch` with `reason=not_found`. A reference mapped to another institution is `mismatch` with `reason=institution_mismatch`.
10. **Findings from low-confidence fields are `manual_review` (severity low), never hard flags.** Threshold `low_confidence_below` (0.6) applies to field confidence = method prior x format validity x OCR confidence.
11. **Duplicate detection is order-based:** a file is flagged only if the same SHA-256 appeared in an EARLIER application (or twice in one application); the first submission is never flagged.
12. **Threshold tuning (DEV only).** `eval/tune_thresholds.py` maximises app-level F1 per defect on the 20 DEV applications and, when F1 ties across a plateau, takes the plateau median. The name-similarity plateau on DEV was the whole grid (50-100): DEV contains no near-miss name pair, so DEV alone cannot determine this threshold. The pre-declared tie-break gives 75 and was NOT changed afterwards. Disclosure: during an M3 sanity check I printed name-similarity margins over the whole corpus (DEV+TEST) to confirm the scorer was not broken; the threshold was not altered because of it. TEST results are reported at the DEV-chosen thresholds, plus a clearly labelled sensitivity table (diagnostic only).
13. **"Structured validation report data source" (MOCK, capability #30)** is interpreted as: the validation report the platform emits is a structured JSON document (per application: findings, verifications, documents) whose institution-history section (previous scrutiny outcome) comes from a MOCK data source (`backend/mock/scrutiny_history.json`, added in M4). It is labelled MOCK everywhere.
14. **Synthetic-data caveat:** the generator and the extractor share a label vocabulary and templates, so extraction/classification accuracy on this corpus is optimistic; defect separability (benign name variants all score 100 after normalisation; injected mismatches <= 81) is also generous. Numbers describe this synthetic benchmark only, with n=4 per defect (2 dev + 2 test).

15. **Actor placeholder (M4):** the API reads `X-Actor` until JWT/RBAC lands in M9; M4 endpoints are therefore unauthenticated by design and must not be treated as secured.
16. **Carry-over of reviewer decisions:** a finding is matched across runs by fingerprint (rule, document sha256, doc type, message); a decision (accept/override/clarification) carries over only when the same finding is re-raised against identical content.
17. **Scans (M6):** 8 dev + 8 test applications (seed 42) are rendered to image-only PDFs at 200 dpi with three degradation levels (Augraphy + rotation/blur/JPEG). The first level definitions were too aggressive (even "light" erased pale sidebar labels); they were recalibrated once after inspecting DEV pages. Level definitions use no TEST data. OCR is RapidOCR (ONNX); scope is printed English only.
18. **Scan metadata:** the PDF creation-date anomaly rule (R-META) is skipped for OCR-sourced documents because a scan's dates record the scanning time, not the issue time.
19. **Image uploads:** PNG/JPEG/TIFF uploads are wrapped into a single-page A4-width PDF, so every document follows the same path (hash, storage, OCR, viewer). The wrapped PDF is what is hashed and stored.
20. **Signatures (M7):** the trust anchor is a synthetic root CA ("MOCK"). Statuses: valid, modified_after_signing, invalid_integrity, untrusted_signer, expired_certificate, signer_not_authorised, error; unsigned documents raise no finding. Tamper-after-signing and integrity failures are high severity; the other statuses use the checklist severity (medium).
21. **Tamper indicators (M7):** heuristics only, on image-only (scanned) pages, never on text-layer pages. The tamper set re-saves every file (clean controls included) at JPEG q95 so re-saving cannot separate classes. Detector thresholds were grid-searched on DEV only (n=32): ELA (z>=30, >=3 blocks) severity low because of its false-positive rate; noise (z<=-2.5, >=10 blocks) and copy-move (NCC>=0.99, 160x24 px glyph-rich patches) medium; stroke-consistency fires on nothing at its clean-safe threshold. Severity is capped at medium in code.
22. **Dataset size:** the tamper set is ~35 MB and the scans ~52 MB; the final zip may need to drop them (see README) if it exceeds ~100 MB.
23. **RBAC (M9):** four roles. institution_user -> own institution only (create/upload/read; no review actions, report or audit). scrutiny_officer and regional_officer -> their own region (review actions, run, report; regional may also trigger verification retries). admin_senior -> everything, plus audit, user list and retention purge. Wrong role -> 403; object outside the caller's institution/region -> 404 so identifiers cannot be enumerated. The user row is re-read on every request, so disabling an account takes effect at once.
24. **Auth limits (MOCK-grade):** HS256 JWT (8 h), bcrypt hashes, in-memory lockout after 5 failed logins per username for 5 min (resets on restart, per process). No refresh/revocation, MFA or SSO. The signing secret is AICTE_JWT_SECRET or a dev key in var/. All demo accounts share one synthetic password (Demo@1234).
25. **Retention:** AICTE_RETENTION_DAYS (default 365). A purge deletes the encrypted file and sets purged_at; metadata, SHA-256, findings and the audit trail stay. Purges are audit-logged with the hash; the file endpoint then answers 410. Runs daily (APScheduler) and on demand (admin).
26. **Tests share one temp var-dir/DB** (tests/conftest.py): engine, storage root and keys are module-level singletons, so per-module temp dirs clobbered each other once more modules existed.
27. **Alerts (M10):** four condition types (finding_open with severity param, manual_review_stale, verification_unresolved, clarification_overdue) configured in backend/config/alert_rules.json; five rules ship, including AL-MEDIUM-OPEN as an example of a rule added by config only. An alert becomes DUE at (condition start + raise_after_hours); condition start for a finding = earliest created_at of any row with its fingerprint (re-runs do not reset the clock). Escalation thresholds are measured from the due time. If the engine was down and several thresholds have passed, the alert jumps straight to the highest level reached. Acknowledged alerts do not escalate. A resolved alert re-opens if its condition recurs.
28. **Notifications:** each raise/escalation writes an in_app and an email_mock row addressed to a role (+region, or institution for the clarification rule). The e-mail channel is MOCK: nothing is sent and no addresses exist.
29. **Alert-timeliness numbers are SIMULATED:** eval/alert_eval.py drives services.clock in 5-minute ticks, so detection lag is bounded by the tick by construction; the number shows the engine meets the tick bound and never duplicates, not real-world latency.
30. **Reports:** CSV/PDF/JSON all derive from the same scoped queries; tests assert CSV counts and PDF text equal the queue tiles. Staff roles only; every export is audit-logged.
31. **TEST discipline (M11):** thresholds (name similarity 75, metadata window, tamper detector thresholds) and OCR preprocessing were fixed on DEV. eval/run_eval.py is the first and only place TEST scans/tamper images were scored. On TEST, `name_mismatch` recall is 0.50 at the DEV-tuned threshold (a higher threshold would have scored 1.00); the configured value was deliberately NOT changed after seeing TEST, and the sensitivity table is published instead.
32. **Packaging:** the zip excludes venv, node_modules, __pycache__, .git, the Augraphy download cache (augraphy_cache, 22 MB, regenerated on demand) and var/ (keys + DB are created on first run). Scans and tamper images ARE included (the zip stays under ~100 MB), so `python -m eval.run_eval` runs as shipped.
33. **UI restyle (post-M11):** the front end now follows the look-and-feel of the AICTE public website (dark utility bar with text-size controls, white brand bar, navy navigation, amber pill buttons, "Approval Process 2026-2027" home panel, LATEST NEWS ticker, three navy-headed cards, footer). Only colour, layout and typography language were reproduced. The official emblem/logo is NOT used (a neutral placeholder mark is shown), and every page states "prototype with synthetic data - not an official AICTE website". Dark mode was removed.
34. **APH cross-check:** the Approval Process Handbook 2024-25 to 2026-27 (supplied PDF) was compared with the validator. Result in backend/config/aph_crosscheck.json (16 items: 3 covered, 5 partial, 8 not covered), served at GET /api/aph-crosscheck and shown on the "APH Checklist" page. It is an engineering cross-check, not an official reading.
35. **Opt-in APH rules:** R-APH-DSC (APH 1.4.6: unsigned document) and R-APH-LEASE-TERM (APH 2.1(e): lease with < 4 years left; 4 is an assumption) ship with "enabled": false so the evaluation numbers are unchanged. Set "enabled": true in the checklist JSON to use them; tests cover both states.
